# Звіт каси кафе — командний проєкт уроку 15

Програма читає місячний файл каси, пропускає зіпсовані рядки з поясненням, друкує звіт і зберігає його в `report.json`.

```bash
python main.py kasa_2024_07.txt
```

```text
Чеків: 4, пропущено рядків: 5
Виторг: 3040.00 грн, середній чек: 760.00 грн
Найкращий день: нд
За днями: пт 860.00, сб 980.00, нд 1200.00
За прийомом їжі: вечеря 3, обід 1
```

Потрібен лише Python 3.10+ і стандартна бібліотека.

## Шість задач

| № | Файл | Що зробити | Використовує |
|---|---|---|---|
| 1 | `rules.py` | `meal_type(hour)`, `day_name(timestamp)` | — |
| 2 | `parsing.py` | `parse_line(line)` | `models.py` |
| 3 | `loading.py` | `read_lines(path)`, `load_orders(lines)` | задача 2 |
| 4 | `stats.py` | `revenue_by_day`, `best_day`, `count_by_meal` | задача 1 |
| 5 | `report.py` | `build_report(orders, errors)` | задача 4 |
| 6 | `output.py` | `save_json(report, path)`, `format_report(report)` | формат звіту задачі 5 |

`models.py`, `main.py`, `check.py` і `tests/` дає викладач — їх не змінюємо.

Що саме має робити функція, написано в її докстрінгу — це **контракт**. Тести задачі перевіряють лише контракт і підставляють заглушки замість чужих функцій. Тому свою задачу можна зробити й перевірити, навіть якщо інші ще не готові.

## Правила команди

1. Одна задача — одна гілка: `task-3-loading`. У `main` напряму не комітимо.
2. Змінюєш лише свій файл і свій рядок у `TEAM.md`.
3. Перед push: `python check.py N` → усі тести твоєї задачі `OK`.
4. Pull Request у `main`, хтось із команди переглядає код і натискає Merge.
5. Після кожного злиття всі роблять `git switch main` і `git pull`.
6. Проєкт готовий, коли в `main` проходить `python check.py all`.

```bash
python check.py        # таблиця: яка задача готова
python check.py 3      # тести задачі 3
python check.py all    # усі задачі + інтеграційний тест
```

Тека `solution/` — розв'язок для викладача. Не підглядай, поки задачу не зроблено.
