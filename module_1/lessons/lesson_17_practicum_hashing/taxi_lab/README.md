## Що показати на занятті

1. **🔬 Хеш-таблиця зсередини.** Ключ → `hash()` → `% місткість` → комірка. Наповнити таблицю зонами NYC
   (+1 / +5 / +50) і подивитися на колізії, зсунуті ключі, коефіцієнт заповнення й розширення таблиці (2/3 → ×2).
   Два режими: кошики-списки (модель з ноутбука) і відкрита адресація (як `dict` у CPython).
   Погані хеш-функції («перша літера», «довжина», «завжди 0») перетворюють пошук на O(n) — графік порівнянь.
2. **⚖️ list · tuple · set · dict.** Таблиця властивостей, що можна хешувати й чому, пастка `{1, 1.0, True}`,
   гонка `x in …` на 1 000 — 1 000 000 елементів і ціна побудови множини.
3. **🧠 Пам'ять.** `sys.getsizeof`, глибокий розмір і `tracemalloc` для 10 тис. — 1 млн номерів; сходинки росту
   list / set / dict; скільки важать `int` і `str` (латиниця, кирилиця, емодзі), кеш малих чисел.
4. **🗄️ NYC Taxi + DuckDB.** Реляційна база як продовження уроку: таблиці, первинний ключ, SQL.
   - Чотири питання двома способами — Python (`Counter`, `set`, `dict.get`) і SQL (`GROUP BY`, `COUNT DISTINCT`,
     `JOIN`) — однакові відповіді, час обох.
   - `EXPLAIN`: `HASH_GROUP_BY` і `HASH_JOIN` — хеш-таблиці всередині бази.
   - Повтори ключів у довіднику зон (56, 103): `dict` перезаписує, `JOIN` «розмножує» поїздки → навіщо `PRIMARY KEY`.
   - Скільки важить одна поїздка: Python-кортеж, колонки numpy, parquet.
   - Карта посадок за зонами.

Перед кожним дослідом є **прогноз**: група обирає відповідь, потім застосунок показує, що вийшло.
